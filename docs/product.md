# 产品与交互规范

本文件是用户可见行为的唯一依据。需求原文见 `.prompt_tmp/initial/prompt.md`；视觉与密度规范见 [ui.md](ui.md)，模块实现见 [architecture.md](architecture.md)。

## 1. 原则

- **想编辑就编辑，想聊天就聊天。** 文件与对话是两种工作重心，由 Paradigm 切换，而不是把两套逻辑缝进同一组 Tab。
- **省心。** 默认开箱即用；界面不出现运行时、协议、路径映射等技术细节；非必要不加 helper text。
- **紧凑。** 常用模块用满每一寸空间；只保留一层面向当前焦点的工具栏；不使用 NavigationBar。
- **不丢工作。** 离开、关闭面板、切换 Paradigm、切换或归档 Session 都不会隐式丢弃未保存内容。

## 2. 顶层结构：Launcher 与 Workbench

应用内有两类“空间”，行为类似系统桌面与其上运行的应用（多用户式隔离，而非同一页面栈）：

| 空间 | 内容 | Back | Home |
| --- | --- | --- | --- |
| Launcher | Apps 网格（内置应用 + 手动添加的三方应用）、少量角落入口 | 无操作 | 停留在 Launcher |
| Workbench | 当前 Session 的全部面板 | 先关闭临时 UI（菜单、弹层、拖拽、临时展开的侧栏），否则回到 Launcher；不关闭 Tab、不切换 Paradigm | 回到 Launcher，Workbench 状态原样保留 |

- Workflow 注册为可选的系统 Home。成为默认桌面后，系统 Home 键始终回到 Workflow Launcher；未设为默认时，系统 Home 离开应用，应用内的 Launcher 入口仍可用。
- 内置应用：**Workbench**、**代理**、**设置**。与三方应用一样出现在 Apps 中，可排序。
- 三方应用默认不显示；通过“添加应用”从已安装的可启动应用中选择后才出现。移除只影响 Apps 列表；内置应用不可移除。
- 点击 Workbench 进入最近使用的 Session。代理 / 设置默认在**当前 Session** 中作为面板打开；长按（右键）菜单提供“在单独的会话中打开”，新建一个只含该面板的临时 Session。
- Apps 支持拖拽排序；长按菜单：打开、在单独的会话中打开（仅内置）、从 Apps 移除、应用信息（三方）。

## 3. Session

Session 是一段连贯工作的上下文，按时间而非项目组织；用户可随时新建、切换、归档。它包含 Paradigm、面板组、Stack 与布局、焦点、阅读位置等 UI 状态，任何时刻离开都能恢复，无需显式保存。

- **临时 Session**：新建时默认类型，无需命名；1 天未使用自动归档。
- **持久 Session**：必须命名（给临时 Session 命名即转为持久）；7 天未使用自动归档。
- **会话视图**（Workbench 角落的小按钮打开）：
  - 持久 Session 列表按“归一化使用频率 + 最近使用时间”排序，最近使用时间权重优先。
  - 临时 Session 以 timeline 呈现，越久远越模糊（字重、透明度、信息量逐级降低），用于快速检索。每项显示时间与主要资源（文件名、对话标题）。
  - 顶部搜索按名称与资源检索；已归档 Session 可查看与恢复。
- **归档保护**：存在未保存内容（Working Resource）时，引用该资源的**最新** Session 不会被自动归档，更旧的引用仍可归档。
- **手动归档**：若 Session 涉及未保存内容，必须明确选择：全部保存 / 保留草稿 / 丢弃。

## 4. Working Resource

打开的面板若对应一个 Resource（文件、对话），而该 Resource 有尚未写回本体的修改，这份修改就是 Working Resource。它不是 UI 状态，也不属于某个 Session。

- 同一 Resource 只有一份 Working Resource，所有 Session 共享；关闭面板、切换 Session、进程被杀后都能恢复。
- 目前主要是未保存文件；对话输入框草稿与待发送附件按对话隔离保存，行为相同。
- 外部修改了已打开的干净文件时静默刷新；有草稿时提示冲突（保留我的 / 使用磁盘版本 / 对比），绝不静默覆盖。

## 5. Paradigm、Stack 与 Panel

**Panel** 引用一个资源或功能（文件编辑器、图片预览、终端、对话、文件浏览器、代理、设置）。**Stack** 是一组以 Tab 呈现、共享一块区域的 Panel。**Paradigm** 是比 Panel 更高一层的结构：决定有哪些区域、区域的角色与整体布局。

| Paradigm | 主内容 | 辅助内容 |
| --- | --- | --- |
| Files | 文件浏览器 + 编辑器 Stacks（可分栏）+ 底部终端 Stack | 右侧独立的对话面板，不混入编辑器 Tab |
| Chat | 对话（ChatGPT App 形态，左侧可收起的对话列表） | 右侧缩减的文件工作台：文件浏览器与编辑器 Stack，终端等不常用部分收起 |
| Solo | 单个应用面板（在单独会话中打开代理 / 设置时使用） | 无 |

- Files 的对话面板头部有“设为主要内容”按钮，带着这个对话进入 Chat；Chat 侧栏可一键回到 Files。切换只改变布局，不重建对话、不重开文件，Files 下的布局在返回时原样恢复。
- 各区域可拖动分隔条调整大小，可收起；窄屏（竖屏）时辅助区域变为可临时展开的覆盖层。
- 同一 Resource 在同一 Session 中只打开一次；再次打开会聚焦已有 Panel。

### 避免重复 Chrome

不形成 App Bar → Stack Tab Bar → Panel Header → Panel Toolbar → Content 的层层嵌套。Stack 的 Tab 行就是唯一的工具栏：右侧放置当前焦点 Panel 提供的常用操作（撤销、重做、保存、搜索等 icon button）与 More 菜单。Panel 自身不再有标题栏。

More 菜单是复合菜单，按类别用 separator 分组：当前资源操作（复制路径、在文件树中显示、发送到对话…）→ 当前 Panel / Stack 布局操作（向右 / 向下拆分、移动到…、关闭其他）→ Session 操作（新建、命名、切换 Paradigm）。

## 6. 拖放

全面支持拖放，拖动时先显示明确的目标提示，松手后作为单一事务提交：

| 拖动对象 | 目标 | 结果 |
| --- | --- | --- |
| Tab | 同一 Tab 行 | 排序，插入位置以竖线指示 |
| Tab / Panel | 其他 Stack 的中心或四边 | 移入该 Stack，或在该边拆分出新 Stack；目标区域半透明高亮 |
| 文件树节点 | 文件夹 | 移动文件（确认后） |
| 文件树节点 / 编辑器 Tab / 系统外部文件 | 对话输入区 | 添加为附件 |
| 文件树节点 / 编辑器 Tab | 终端 | 粘贴（经过 shell 转义的）路径 |
| Apps 图标 | Apps 网格 | 排序 |

## 7. Files 模式细节

- **文件浏览器**：树形；新建文件 / 文件夹、重命名、删除（移入回收站，可撤销）、移动、复制路径。“+”上传：拍照、相册、设备文件，写入当前选中目录。`.workspace` 内部目录默认隐藏。
- **编辑器**：sora-editor，只需语法高亮；撤销、重做、保存外提到 Stack 工具栏；软键盘可见时显示与终端共用的特殊键行；图片直接预览。
- **终端**：xterm.js，运行在工作区环境中（默认用户 `work`，工作目录为工作区根）。
  - 点击 URL 用系统浏览器打开；点击本地文件路径（含 `path:line:col`）在编辑器中打开并定位。
  - 拖入文件粘贴路径。
  - 软键盘上方的特殊键行：Esc、Tab、Ctrl、Alt、方向键、Home/End、PgUp/PgDn 以及 `| ~ / - _` 等常用字符；Ctrl/Alt 为可锁定的修饰键。
  - 多个终端作为同一 Stack 的 Tab。

## 8. 对话

对话界面按 ChatGPT App 形态设计，同时接入 Codex App-Server 与 Claude Code，功能完整（覆盖清单见 [agents.md](agents.md)）。

- **进行中**：助手输出无气泡、流式 Markdown；思考与工具活动以可折叠的紧凑行呈现；输入区发送键变为停止键，可继续输入以排队或引导。
- **完成后**：最终回复完整呈现，下方为复制等操作行；过程细节折叠为一行摘要。
- 对话由原生 Compose 流式渲染 Markdown、表格、行内/块级数学与代码，代码块带复制；xterm 终端继续使用离线 WebView。
- **模型 + 推理强度**由一个滑块选择：模型沿滑块分段排列，每个模型内部的档位即推理强度。选择对下一轮生效。
- **附件**：“+”菜单（拍照、相册、设备文件、工作区文件）与文件浏览器的上传共用同一实现；支持拖放添加；待发送附件以缩略条展示，可移除。
- **审批与提问**：代理发起的命令、文件修改、权限、用户输入、MCP 请求以内联卡片呈现，必须由用户明确选择；应用从不自动批准。
- 对话列表可搜索、重命名、归档；新对话选择后端（Codex / Claude Code）由上次选择记忆。

## 9. 悬浮窗

常用的全局工具，需要精心设计。

- 收起态：小圆形按钮，可拖动，松手自动贴边并半隐藏；不遮挡时降低不透明度。
- 点击展开为紧凑面板，点击面板外空白处关闭：
  - 快速切换应用：Apps 中已添加的应用，另可额外选择仅在悬浮窗中出现的应用；
  - 亮度滑块；
  - 黑白（灰度）模式开关；
  - 锁定屏幕。
- 每个动作以真实结果为准：权限或 root 不可用时，对应控件显示不可用并可一键前往授权，不以开关状态冒充系统状态。

## 10. 代理

类似 ClashMetaForAndroid，不提供配置覆写（用户直接编辑配置文件）。使用最新 Mihomo 内核，root 下以 TUN 运行；配置位于工作区根的 `.workspace/services/proxy/`。

- 单屏：启停、模式（规则 / 全局 / 直连）、代理组与节点选择、延迟测试、实时流量；日志与连接为次级视图。
- 检测到其他 VPN / TUN 正在运行时明确提示冲突，不静默接管。

## 11. 设置与工作区

- 先选择并保存工作区连接，再进入工作台；当前只实现本机连接。连接断开时工作区修改不可用，重连后恢复 Engine 的权威状态。
- 用户文件位于工作区根；配置与内部状态位于 `<workspace-root>/.workspace/`。Engine 是工作区唯一写入者；客户端仅保存连接配置及工作区下发的本地配置缓存。
- Environment 包含完整运行环境；`.workspace/env.json` 描述 Python/Node 多版本、软件包、变量和构建后脚本。两个 ABI 均交付定制镜像，首次默认环境无需联网安装工具链；构建验证失败保留旧环境，有运行进程时等待用户重启后切换。
- Codex、Claude Code 和终端只能在环境内执行；未就绪时显示真实准备或错误状态。
- 设置包含：外观与密度、对话后端账户、环境状态、悬浮窗、默认桌面、权限状态、关于。只展示用户需要决策的内容。

1.0.0 不提供 Legacy 数据迁移：不自动导入、改写或搬移旧 Session、对话、草稿、账户与旧配置。
