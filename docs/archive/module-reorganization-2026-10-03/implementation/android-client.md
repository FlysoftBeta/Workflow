# Android client

The Android application connects to a Workspace Engine, renders its state, and executes local Android capabilities. Its feature controllers and ViewModels are presentation coordinators. Durable sessions, layouts, drafts, environment state, and service configuration belong to the Engine. Only connection profiles and workspace-delivered local configuration may be durably cached by the client. The [architecture](architecture.md) and [protocol](protocol.md) define that boundary; the [UX specification](../ux/README.md) defines what the user sees.

## Connection and feature composition

`AppGraph` assembles the embedded bootstrapper, transport, workspace projection, service ports, and platform executors. The selected connection profile is saved before startup. After an exact-version handshake, the client reads the authoritative snapshot and starts connection-scoped consumers. The connection session exposes protocol identity and service ports, not a host workspace `File`; only embedded bootstrap resolves the local root. Failure retires that connection, cancels its consumers, marks its projection failed, and releases the corresponding foreground-service leases. Reconnection loads Engine state again rather than reviving a local repository.

Feature packages do not import one another. Shared panel contracts and injected ports connect actions such as opening a file from chat, showing account settings, or selecting a proxy log. Production panel wiring obtains services through those ports; test fixtures use scoped providers instead of a process-global substitute. Reading an image, importing an external URI, or resolving an attachment still goes through Engine file APIs. Android staging caches are bounded and disposable.

`LocalRuntimeService` coordinates the local connection and capability lifetimes. A foreground lease follows the work that requires it, including a live proxy guardian. Lifecycle handling must distinguish an obsolete connection's callbacks from the active one and must confirm foreground startup before a queued release can stop the service. Reconnecting cannot authorize work using a retired service instance or stale configuration.

## Compose and design resources

The client targets API 28 and uses Compose with Material 3 Expressive. Shared components and tokens live in `ui.design`; the theme supplies `LocalMinimumInteractiveComponentSize` from its touch-target token rather than relying on the visual icon size. Root layouts account for `WindowInsets.safeDrawing`. The activity uses `adjustResize` and IME insets, so input behavior cannot depend on API-30-only IME animation APIs.

Generated theme colors use `SchemeTonalSpot` with seed `#286B57` and contrast zero. `tools/design/generate-colors.mjs` writes the checked-in colors used by the client. The launcher's geometry and visual treatment are described in UX; historical external source-art paths are not build dependencies. Material Symbols Rounded are pinned offline vector assets with manifests and licenses, rather than a downloaded icon font. JetBrains Mono NL is bundled with its OFL license. The [dependency document](dependencies.md) identifies those asset sources and regeneration tools.

PackageManager labels and icons are loaded and cached on a background dispatcher. Compose does not call `loadLabel` or `loadIcon` while rendering launcher rows. File I/O, syntax-asset loading, thumbnail decoding, and expensive parsing also remain off the main thread. Application-authored JSON follows the two-space formatting convention; that presentation convention must not rewrite opaque vendor documents or change wire semantics.

## Chat and tool projections

Android's `AgentHub` is a disposable `chat.snapshot`/`chat.watch` projection and `chat.command` client. Its production dependency is `:agent-model`; vendor adapters, process launchers, conversation-index writers and installation scripts are excluded. Ordered events use the shared reducer, metadata replaces the previous Engine projection, and a service epoch change or journal gap requires a fresh snapshot. Frozen snapshot transfers are bounded and checked for offset continuity.

Sends retain a client operation ID and submit the exact Engine-saved composer revision. Engine owns deduplication and acknowledgement; Android restores failed input without automatically replaying an ambiguous submission. Approval cards carry the process epoch from their displayed request, preventing an old card from answering a reused vendor ID. Account flows, login methods, permission defaults and tool readiness follow current Engine metadata rather than a separate remembered business state. Claude install controls call `environment.tools.install` with a tool ID and retry flag; the client contains no release URL, version pin, vendor home or executable path.

## Native chat rendering

The chat renderer is native Compose. CommonMark parses Markdown into a block model; Compose renders prose, code, tables, activities, approval cards, and controls. There is no chat WebView bridge. Mathematical notation uses JLaTeXMath drawables rendered through Canvas. Drawable construction runs on a background dispatcher under a mutex because the upstream parser has shared symbol tables; input and output-size checks bound unsafe or impractical expressions, and a small cache avoids rebuilding unchanged formulae.

`ConversationController` conflates protocol bursts and projects transcripts on `Dispatchers.Default`, with a 64 ms pause between projection passes. A per-controller Markdown cache reparses changed messages and bounds retained characters. `NativeTranscriptProjector` flattens messages into stable keyed block rows for `LazyColumn`, so a long answer is virtualized below the turn level instead of becoming one enormous layout item.

Scroll state records a stable row anchor, offset, and follow mode in panel view state. When the requested historical anchor has not loaded, the renderer requests earlier history before restoring it. Completed messages reuse parsed content, while streaming messages update only their changing projection. Link callbacks route safe web URLs to Android and workspace paths through panel navigation. Selection and copy actions operate on native text and the preserved source content.

## Editor, terminal, and drag adapters

Sora remains the text-editor adapter. Its controller coordinates authoritative file/draft state, cursor, logical reading line, wrapped-column position, partial-row offset, and horizontal scrolling. A resize or IME change must preserve the reading position even when the caret is elsewhere. The split-pane contract recommends delaying expensive Sora/WebView relayout until a divider drag has stopped and a 100 ms settling interval has passed; this is adapter guidance, not evidence that every resize path applies a uniform debounce.

Only xterm uses WebView. Assets are local and transpiled for Chromium 66, with a bundled built-in compatibility layer for Android 9. The WebView bridge carries input, resize, selection and navigation. `TerminalHost` retains connection-scoped UI attachments; stable IDs, ordinal, title, cwd, retained bytes, generation, restart and reference cleanup belong to Engine `terminal.*` resources. Android has no reference reaper or environment restart callbacks. Cancelling an attachment never stops its Engine resource.

A terminal read applies metadata and matching bytes together. Generation changes and clipped windows reset the disposable decoder/scrollback, and the renderer reads generation and output as one snapshot. Reading continues after EOF to observe another client's restart or rename. Rename, clear and restart submit Engine operations; UI reset follows their authoritative frames. A real environment activation restores resources inside Engine, while a no-op restart leaves them alone. JNI host-shell support is instrumentation-only.

In-app drag and drop uses a Compose overlay and shared target geometry. External Android drags enter the same model through `dragAndDropTarget`, with URI permission and import handling at the platform boundary. Layout drops submit one `LayoutOp`; drag hover does not become a sequence of durable layout writes. Files dropped on chat or terminal content use file-transfer semantics instead of panel movement. Menus and accessibility actions provide alternatives to dragging, including region resizing.

External imports and attachments share Engine-backed import and file-selection services. The client supplies a source length and stream factory, sends bounded chunks, and cancels an upload on failure or cancellation. URI and camera staging is capped at 512 MiB per import and tied to the originating connection instance. Engine allocates a collision-free destination from directory and name during commit and returns the final path; Android does not create directories, scan names or parse error text to decide a retry. It does not bypass Engine to write user files.

## Verification

Source architecture guards reject production vendor/process dependencies and host workspace-path exposure. `TerminalAttachmentTest` covers metadata/byte generation alignment, repeated EOF, remote restart observation and cancellation without process termination using a managed fixture. These tests do not establish real runtime execution. `NativeTranscriptTest` covers native conversation rendering, while `OfflineRendererTest` exercises the terminal's real Android WebView. Editor and workbench tests separately cover view restoration, IME and window changes, layouts, and drag behavior. Node or JVM tests cannot establish Android input or rendering acceptance on their own. The [native-chat](../archive/implementation-1.0.0/reports/rewrite/native-chat.md), [editor](../archive/implementation-1.0.0/reports/rewrite/editor-repair.md), [workbench](../archive/implementation-1.0.0/reports/rewrite/workbench-qa.md), and [client-boundary](../archive/implementation-1.0.0/reports/rewrite/client-boundary.md) reports describe recorded checks. [Status](../status.md) keeps those results separate from untested devices and live-account scenarios.
