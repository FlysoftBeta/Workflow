# Rust workspace client boundary acceptance

## Changed boundary

- `RemoteWorkspaceStore` file import now requires the exact byte count and an `InputStream` factory. Byte arrays stream directly; Android imports use their existing staged file length. Each upload sends `{path,size}`, uses at most 64 KiB per block, verifies offsets and source length, closes the source, and cancels incomplete/failed/cancelled uploads. No extra client workspace storage was introduced. Existing destinations and racing publication failures remain Engine decisions.
- Configuration CAS accepts Engine's successful `kind:conflict` value as well as its structured conflict error, accepts the accompanying authoritative snapshot, then reapplies the user's transform. Configuration, original unknown fields and expected revision are captured together. This repairs the initial settings/watch/network-report race found by the editor acceptance.
- The serial command lane now waits for its own explicit turn before starting each operation. Caller cancellation removes queued work and cannot kill the lane; disconnect cancels pending work. Stale watch results cannot replace newer command projections. Incoming sessions/layouts are decoded without the reference store's local layout repair path; invalid layouts fail instead of inventing replacement state.
- RPC hello validates the exact protocol, Engine version and required capabilities/limits; repeat calls for the same identity reuse the successful handshake. UTF-8, integer fields and JSON-RPC response shape are checked. Transport failure closes the transport once, fails all pending requests, preserves the first failure reason and rejects future calls.
- Android startup now calls an actual `EmbeddedWorkspaceBootstrapper : WorkspaceBootstrapper`. It owns the APK Engine process and filtered Android environment; unsupported remote endpoints remain explicit failures. Cancellation during the bootstrap handoff also retires a process that would otherwise escape the caller.
- Connection profiles are saved before bootstrap. Connection failure/disconnect clears the current session, marks its projection failed, cancels its child scope/network callback and releases its unique foreground lease. Reconnect creates a new token/store and reads Engine state. The manager exposes cached presentation preferences for the connection screen; only `client.config` appearance/launcher/overlay/terminal fields are cached, keyed by connection id. Agent, session, draft and service state never enter that cache. Cache IO is serialized; a cache write failure is observable without replacing live Engine state.

The import port change necessarily touched `WorkspaceStore`, its test-only reference implementation and the Android importer call site. No host agent/terminal fallback, remote transport implementation or daily tablet changes were added. MainActivity/AppGraph/terminal disposal and server no-replace publication were handled by root integration.

## Reproducible verification

All Gradle builds used `flock artifacts/.gradle.lock`. The four Engine integration tests use the existing host Rust Engine executable (`engine/target/debug/workflow-engine`, or `WORKFLOW_ENGINE`) and separate temporary roots; they do not fake Engine results or run host terminal/agent workloads. The remaining nine tests use explicit transport fixtures to force malformed frames, cancellation and response ordering.

- `:core:test --tests 'top.flysoftbeta.workflow.core.connection.*'`: **13 tests passed, 0 skipped** (`artifacts/client-boundary/build-v4.log`, copied JUnit XMLs under `artifacts/client-boundary/junit/`). Four tests use the actual Rust Engine: chunked/empty upload, destination race and no overwrite, source short/long/exception/cancellation cleanup, draft/session/archive/disconnect/reconnect persistence, and external config CAS with unknown-field preservation. Nine transport/projection tests cover handshake rejection, repeated hello, malformed response failure, request timeout/late response, stale watch ordering, cancelled queued work, invalid layout rejection and pending-call retirement.
- Final full `:core:test :app:compileEmulatorDebugKotlin`: **225 tests passed, 0 skipped**, and Android production compilation passed (`artifacts/client-boundary/final-host.log`).
- `:app:assembleEmulatorDebug :app:assembleEmulatorDebugAndroidTest`: passed; the final source snapshot was rebuilt successfully in `build-v5.log`, and both APKs were copied inside the same lock to `artifacts/client-boundary/apk/`.
- `ConnectionBoundaryAcceptanceTest`: implemented for wrapper-managed emulators only. It exercises the real application manager and packaged Engine under app UID: actual chunked creation, Engine draft persistence, scoped local cache, forced transport failure, scope/lease retirement, retry, explicit disconnect and unsupported remote rejection. The first actual app run passed **1/1** in `device-v1.log`. The final source snapshot repeat also passed **1/1** in `device-v2.log` (4.328 s). Both runs used `WORKFLOW_EMULATOR_PORT=5894 tools/with-emulator.sh`, API 28 x86_64, 1536 MiB and disk ANDROID_TMP; their wrapper processes exited and no daily device was accessed.

## Limits

Host protocol tests are not Android sandbox acceptance. This boundary scope does not establish ARM64, authenticated vendor model or complete environment lifecycle acceptance. Final UI/import verification must use the normal upload route and the server's no-replace fix; no file seeding fallback counts as that acceptance.
