# Container compatibility runtime

`workflow-runtime` runs the complete workspace environment through the maintained Rust tracer and
the freestanding loader. It implements path, identity and metadata virtualization, image
installation and process compatibility. It has no host-execution fallback. The Server invokes
this executable for every production terminal and agent process.

`src/` is one maintained source tree for Linux x86_64, Android x86_64 and Android aarch64.
`main.rs` selects the supported target set and invokes the shared CLI. `cli` handles commands;
`tracer`, `sys`, `exec` and `arch` implement tracing and execution; `path`, `guest`, `ident`, `meta`
and `install` implement the virtual environment; and the remaining modules support memory,
scratch storage, JSON and digests. There are no per-target copies of these modules.

Small `cfg(target_os)` and `cfg(target_arch)` declarations, functions and blocks retain genuine
libc and kernel ABI differences: errno/ptrace/stdio/signal declarations, register and stat layouts,
syscall numbers, Android system binds, x86 legacy syscall rewrites and architecture-specific
seccomp filters. The private `platform_empty_*` constructors retain each target's explicit
aggregate initialization; `platform_expr_*` isolates signal-field access and wait-status decoding.
These are maintained Rust sources, not generated output or a build-time translation of archived C.

[The merge audit](MERGE_AUDIT.md) classifies the divergences and explains the equivalence gate.
Run it from the repository root with the pinned Rust toolchain and all three target standard
libraries installed:

```sh
python3 engine/environment/runtime/tools/test-platform-merge.py
python3 engine/environment/runtime/tools/check-platform-merge.py
```

The checker compares compiler-expanded items for all 42 target/module pairs against the retained
pre-extraction Git commit. It accounts for explicitly audited spelling changes while retaining
signatures, layouts, values and control flow. It needs no third-party Python packages and performs
no linking or target execution. This comparison complements host and device acceptance; ARM64
compilation and source equivalence do not establish ARM64 device behavior. The hand-rolled JSON
and SHA-256 implementations remain in place; adopting maintained libraries is a separate
dependency/lockfile follow-up.

`inventory/syscalls.tsv` is the declarative syscall classification input. The checked-in
`src/syscalls.rs` is generated by `tools/generate-syscalls.py`; `src/sysinv.rs` selects the proper
ABI and applies the default-deny inventory. Verify the generated file before building:

```sh
python3 engine/environment/runtime/tools/generate-syscalls.py --check
```

`build-host.sh` and `build-android.sh` compile and stage the runtime with its loader while holding
the shared build lock. Cargo jobs stay at two or fewer. Set `WORKFLOW_BUILD_LOCK_HELD=1` only when
the caller already holds `artifacts/.gradle.lock`. All outputs belong under ignored `artifacts/`
or `engine/target/`.

The [acceptance directory](tests/README.md) separates native guest/oracle workloads, the Android
test app and device drivers. `test-host.sh` and `test-android.sh` are the supported entry points;
the latter uses the repository's single AVD wrapper. The
[runtime guide](../../../docs/engine/runtime.md) explains compatibility limits,
and the [testing guide](../../../docs/development/testing.md) defines the evidence required for each
ABI and Android target.
