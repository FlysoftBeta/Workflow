# Container compatibility runtime

`workflow-runtime` runs the complete workspace environment through the maintained Rust tracer and
the freestanding loader. It implements path, identity and metadata virtualization, image
installation and process compatibility. It has no host-execution fallback. The Server invokes
this executable for every production terminal and agent process.

`src/main.rs` selects `src/host/` for Linux x86_64, `src/android_x86_64/` for Android x86_64, or
`src/android_aarch64/` for Android arm64. Each target keeps ABI-sensitive types and syscall details
together. Within each target, `cli` handles commands; `tracer`, `sys`, `exec` and `arch` implement
tracing and execution; `path`, `guest`, `ident`, `meta` and `install` implement the virtual
environment; and the remaining modules support memory, scratch storage, JSON and digests.
These are maintained Rust sources, not generated build output, and are not regenerated from the
archived C implementation.

`inventory/syscalls.tsv` is the declarative syscall classification input. The checked-in
`src/syscalls.rs` is generated by `tools/generate-syscalls.py`; `src/sysinv.rs` selects the proper
ABI and applies the default-deny inventory. Verify the generated file before building:

```sh
python3 engine/runtime/tools/generate-syscalls.py --check
```

`build-host.sh` and `build-android.sh` compile and stage the runtime with its loader while holding
the shared build lock. Cargo jobs stay at two or fewer. Set `WORKFLOW_BUILD_LOCK_HELD=1` only when
the caller already holds `artifacts/.gradle.lock`. All outputs belong under ignored `artifacts/`
or `engine/target/`.

The [acceptance directory](tests/README.md) separates native guest/oracle workloads, the Android
test app and device drivers. `test-host.sh` and `test-android.sh` are the supported entry points;
the latter uses the repository's single AVD wrapper. The
[runtime guide](../../docs/implementation/container-runtime.md) explains compatibility limits,
and the [testing guide](../../docs/development/testing.md) defines the evidence required for each
ABI and Android target.
